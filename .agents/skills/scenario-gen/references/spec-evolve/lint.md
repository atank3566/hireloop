# lint — provisional/미해결 보고 (비블로킹)

스펙 진화·생성은 불확실성 때문에 멈추지 않는다. 대신 **최종 응답에서 미해결 항목을 모아 보고**해 사용자가 정정할 수 있게 한다. 산출물(스펙·시나리오)은 그대로 낸다.

## 무엇을 미해결로 잡나

| 항목 | 출처 | 메시지 예 |
|---|---|---|
| `provisional` keyRole 잔존 | `key-roles.md` | "필드 '검사구분' keyRole 미확정(none 으로 가정) — 조회조건이면 알려주세요" |
| 구조 미제공 추론 가정 | `routing.md` / frontmatter `assumptions` | "마스터-디테일을 주문↔주문상품으로 추론함 — 다르면 알려주세요" |
| 모호한 화면 종류 | `routing.md` | "'재고'를 현황조회로 해석함" |
| 기본값 단서 없음 | `conventions.md` | "기간 기본값 단서가 없어 최근 1개월로 가정" |

## 출력 형식 (최종 응답에 1블록)

```
미해결 (비블로킹):
- [provisional] 검사구분 → none 으로 가정. 조회조건이면 알려주세요.
- [assumption]  마스터-디테일 = 주문 ↔ 주문상품 (추론). 다르면 정정 가능.
산출물은 위 가정 위에서 생성했습니다. 정정하면 해당 부분만 다시 진화합니다.
```

## 규칙

- 미해결이 **있어도** 스펙(`.spec.md`)·시나리오(`-scenario.json`)는 산출하고 `flex-scenario validate` 까지 통과시킨다.
- 미해결이 **없으면** 이 블록을 생략한다.
- 이 lint 는 `flex-scenario validate` 의 cross-check(스키마/구조 검증)와 별개다 — validate 는 "형식이 맞나", lint 는 "추론이 맞나"를 본다. 둘 다 통과/보고해야 완료.
