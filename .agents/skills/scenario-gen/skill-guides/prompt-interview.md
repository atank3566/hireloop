# Prompt Interview — 비대화형 5질문 자기-답변

> CLI 파이프(`flex-scenario gen`) 는 사용자에게 되묻는 통로가 없다. 모호 입력(L1~L2) 에서도 산출물은 **JSON 한 덩어리** 로 떨어진다. 그 결과 모델이 어떤 가정으로 시나리오를 만들었는지 외부에서 보이지 않아 사용자가 redirect 할 수 없는 게 병목 6.
>
> 이 가이드는 그 병목을 **모델이 자기 자신에게 5질문을 던지고 답을 시나리오에 명시적으로 기록** 하는 절차로 해소한다. 모드는 **비대화형 한 가지** — Claude Code 대화형은 별도 운용 (사람이 직접 묻고 답함).

## 적용 시점

- SKILL.md §시퀀스 **3 (요청 분석) 직후, 4 (examples Read) 직전**.
- 케이스 한 줄에 도메인만 적힌 L1 / 도메인+기능만 적힌 L2 케이스에서 특히 중요. L4~L5 풀스펙 케이스는 사실상 no-op (이미 답이 다 적혀 있음).

## 5질문 — 자기 답변 체크리스트

비대화형이므로 **모델이 직접 답을 만든다**. 답은 케이스 본문에서 추출 가능한 것 → 도메인 상식 추론 → 시나리오 표준 default 순으로 선택.

| # | 질문 | 답의 형식 | 추출 단서 / 기본값 |
|---|---|---|---|
| Q1 | **무슨 화면인가** (한 문장 정의) | 자유서술 1줄 | 케이스 첫 문장 우선 |
| Q2 | **Step 수와 흐름** | `N step (Step1: ... → Step2: ... → ...)` | 케이스에 명시 없으면 — 단순 입력 폼: 1, 입력→확인: 2, 입력→내역→확인: 3, 다중 입력 단계: 3~5 |
| Q3 | **각 Step 의 핵심 필드/컨트롤** | Step 별로 1줄: `Step1: 필드a/필드b/...` | 케이스에서 콤마/줄바꿈으로 묶인 항목 추출 |
| Q4 | **DataConnection 모드** | `query / new / update / detail` 중 어떤 조합 | 리스트/반복 표시 → `query`, 신규 입력 → `new` (mock 면제), 활성 섹터 편집 → `update`, 단건 조회 → `detail` |
| Q5 | **완료 후 동작** | `Step.Next` / 닫기 / 메시지 / 다음 화면 | 케이스에 명시 없으면 — 최종 Step 의 "제출/저장" 버튼 → `intent.script:{kind:'dialog', type:'Completed'}` + `MOVETYPE_INIT` 로 처음으로 복귀 |

> 5질문 외에 추가로 결정해야 할 슬롯(예: BackButton 표준 적용 여부 / Combo 의 다이얼로그 호스트 자식 / 카테고리명 컨벤션) 은 SKILL.md §"절대 금지" 와 cross-check 가 강제하므로 5질문에 포함하지 않는다 — 표준 자체로 결정됨.

## `__notes` 슬롯 — 답을 시나리오 root 에 기록

자기-답변 결과는 시나리오 root 의 `__notes` 슬롯에 **5~7줄, 한 줄 한 답** 으로 기록한다. 이 슬롯은 `schema/v1/scenario.schema.json` 에 화이트리스트로 등재되어 strict-fields 를 통과한다.

### 형식

```jsonc
{
  "Steps": { ... },
  "StartSteps": [ "Step1" ],
  "__notes": [
    "Q1: 출장 경비 정산 — 3-step (기본정보 → 비용항목 → 확인) 입력 화면",
    "Q2: 3 step — 케이스에 'Step 1/2/3' 명시되어 그대로 채택",
    "Q3-Step1: 출장지/부서/시작일/종료일/목적",
    "Q3-Step2: 비용 시트 (사용일/항목/금액/영수증/비고) + read-only 합계",
    "Q3-Step3: Step1+Step2 요약 (read-only Label / Input)",
    "Q4: Step2 비용 시트는 DataUsage:'query' (반복 입력). 그 외 Step 은 단일 입력 폼이라 명시적 DC 불필요",
    "Q5: Step3 '제출' 버튼 → dialog(type:'Completed') + MOVETYPE_INIT 으로 첫 Step 복귀"
  ]
}
```

### 기록 원칙

1. **각 줄은 `Q<번호>: ...` 또는 `Q<번호>-Step<N>: ...` 로 시작** — 사용자가 어떤 질문에 답한 줄인지 즉시 파악 가능.
2. **케이스 본문에서 추출했는지 / 추론했는지 구분** — 추론한 경우 답 뒤에 짧은 근거 (`(케이스에 명시 없어 N step 단순 폼으로 추정)`) 한 마디 덧붙임. 사용자가 redirect 할 때 추론 부분만 골라 수정 가능.
3. **5~7줄 권장, 12줄 한도** (schema `maxItems:12`). 그 이상 필요하면 케이스가 충분히 구체적이라 자기-인터뷰가 불필요한 단계 — 그대로 본문 작성에 집중.
4. **결정만 기록, 설명 금지** — "그래서 이렇게 했다" 는 적지 않는다. 결정 자체가 시나리오 본문에 펼쳐져 있다.

## 모드 판별

CLI 비대화형 호출에서만 `__notes` 를 채운다. 사람이 Claude Code 에서 직접 SKILL 을 호출한 대화형 흐름에선 모델이 사용자에게 1~2개 되묻고 진행하므로 `__notes` 슬롯은 비워둔다 (또는 사용자가 결정한 답을 같은 형식으로 기록).

```
case.md → 사용자 통로 없음? (CLI 파이프 / OneShot)
  ├─ Yes → 5질문 자기-답변 → __notes 기록 → 시나리오 작성
  └─ No  → 모호 슬롯 1~2개 사용자에게 되묻기 → 답 받고 진행 (__notes 비움)
```

판별 단서:
- 환경변수 `FLEX_INTERACTIVE=1` 이 있으면 대화형.
- 그 외엔 비대화형으로 가정 — `flex-scenario gen` 은 항상 비대화형.

## L1/L2 케이스 — 무엇을 추정해야 하나

L1 (도메인 한 단어), L2 (도메인+기능) 케이스에서 자주 빈 슬롯이 되는 항목과 표준 default:

| 빈 슬롯 | 표준 default | 비고 |
|---|---|---|
| Step 수 | 단순 폼 1 / 입력→확인 2 / 입력→내역→확인 3 | 케이스에 "한 화면" 같은 단서가 있으면 1, "확인" / "결재" 가 있으면 2~ |
| 필드 종류 | 도메인 상식 5~7개 + 메모/비고 1개 | 휴가신청: 신청자/부서/시작일/종료일/사유. 견적서: 거래처/품목/수량/단가/금액 |
| 데이터 모드 | 단건 폼은 명시 안 함. 시트/리스트가 있으면 `query` | `new` / `update` 는 케이스에 "수정/등록" 명시될 때만 |
| BackButton | 모든 Step `UseBackButton:true` + 첫 Step 닫기 / 후속 Step 이전 Step 복귀 | 표준이므로 5질문 외 자동 |
| 완료 동작 | `intent.script(dialog)` + `MOVETYPE_INIT` | "처리되었습니다" 한 줄 |

## 안티패턴

- **`__notes` 에 본문 설명을 적는다** — 결정 자체는 본문에 펼쳐져 있어야 한다. `__notes` 는 *결정 근거* 만.
- **5질문 모두 그대로 적는다** — 케이스에 이미 답이 있는 질문은 생략 가능 (L4~L5). `__notes` 는 결정한 *추론 부분* 만 적어도 충분.
- **`{=Field}` 토큰으로 Step 간 값 전달을 적는다** — Step 간 값 전달은 [INTENT.md §`copyStepValues`](../runtime/v1/intent-system/INTENT.md) 가 정답. `__notes` 와 무관.
- **사용자에게 되묻는 문구를 답에 적는다** — 비대화형에서 "어떤 도메인을 원하시나요?" 는 의미 없다. 자기 답을 만들어 기록.

## 측정

- 비대화형 호출에서 `__notes` 가 비어 있으면 (L1/L2 인데도) 자기-인터뷰 누락 — 회귀.
- `__notes` 가 7줄 초과 + L4/L5 인 경우 — 과잉 기록 (케이스가 이미 구체적이라 자기-인터뷰 불필요).
- 사용자가 결과를 보고 "이 가정이 틀렸다" 며 redirect 한 경우, 어떤 Q 항목이 어긋났는지 `__notes` 가 즉시 보여줘야 한다.
